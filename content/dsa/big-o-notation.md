**Big O notation** describes how an algorithm's cost grows as input size grows. It focuses on growth rate, not exact timing.

Common examples:

- `O(1)`: constant time
- `O(log n)`: logarithmic time
- `O(n)`: linear time
- `O(n log n)`: common efficient sorting time
- `O(n^2)`: quadratic time

Big O is usually used for [[time-complexity|time complexity]] and [[space-complexity|space complexity]]. It helps compare approaches before implementation details or hardware differences matter.
